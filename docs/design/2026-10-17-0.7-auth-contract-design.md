# auth-ui 0.7 설계: 인증 계약 정합 (오류 판독 · 경로 · OAuth · 훅)

**날짜**: 2026-10-17
**상태**: 확정 (구현 대기)
**대상 버전**: 0.7.0 (minor — 추가 위주, 기본 동작 유지)
**관련 설계**: `@withwiz/toolkit` 인증 계약 표준화 설계(toolkit 저장소 `docs/auth/2026-10-17-auth-contract-standard-design.md`)

## 배경

toolkit 은 인증 오류 응답을 표준 형태 하나로 정리한다(toolkit 0.21 에서 선택, 0.22 에서 기본값).
auth-ui 는 지금 **문자열형 `error` 만** 읽기 때문에, toolkit 이 기본값을 바꾸기 전에 두 형태를 모두
읽도록 먼저 발행해야 한다. 같은 기회에 소비자가 우회 코드를 두게 만들던 고정값과 누락을 정리한다.

### 현재 동작의 문제

| 위치 | 문제 | 소비자가 겪는 일 |
|---|---|---|
| 모든 폼 | 실패 응답에서 `data.error`(문자열)만 표시 | 표준 응답(`error` 가 객체)을 받으면 `[object Object]` 가 표시되거나 기본 문구만 남는다 |
| 모든 폼 | `details.fieldErrors` 를 읽지 않음 | 서버의 필드별 사유(비밀번호 정책 등)가 화면에 나오지 않아, 소비자가 사유를 문자열 `error` 에 따로 실어야 한다 |
| `LoginForm` | 미인증 판정이 문자열 `code === 'EMAIL_NOT_VERIFIED'` 에만 의존 | 표준 응답의 `key` 로는 판정되지 않는다 |
| `LoginForm`·`SignupForm` | `hooks.onError(message)` 가 문구만 넘김 | 오류 종류에 따라 다른 UI 를 띄우려면 소비자가 문구를 비교해야 한다 |
| `ForgotPassword`·`ResetPassword`·`EmailVerification` 폼 | `hooks` 가 없음 | 성공·실패 후처리(분석 이벤트, 안내 전환)를 붙일 자리가 없다 |
| `SignupForm` | 네트워크 오류에서 `onError` 를 부르지 않음 | 실패 경로마다 훅 호출이 다르다 |
| `LoginForm` | `/forgot-password`·`/signup`·`/auth/magic-link` 고정 | 경로가 다른 앱은 링크를 쓸 수 없고, 매직링크 버튼은 경로가 없으면 404 로 이동한다 |
| `SignupForm` | `/login` 고정 | 같은 문제 |
| `ForgotPassword`·`ResetPassword` 폼 | `'Failed'`·`'Network error'` 영문 고정 | 다국어 화면에 영문이 섞인다 |
| `OAuthButtons` | 제공자 3종 고정, 라벨 `Continue with …` 영문 고정, `mode` 미사용 | toolkit 이 지원하는 meta·microsoft 버튼을 그릴 수 없고, 가입 화면도 "Continue with" 로 나온다 |
| `OAuthButtons` | `/oauth/login` 실패 응답을 조용히 무시 | 사용자는 아무 반응 없이 버튼만 다시 활성화되는 것을 본다 |
| `AuthProvider.login` | `data.error` 로 `Error` 를 만듦 | 표준 응답에서 메시지가 `[object Object]` 가 된다 |

## 목표

1. 두 오류 형태(표준·문자열형)를 모두 읽는 내부 판독기 하나로 모든 폼의 오류 처리를 통일한다.
2. 필드별 오류를 해당 입력 아래에 표시한다.
3. 오류 정보를 구조화해 훅에 넘기고, 모든 폼에 같은 훅을 둔다.
4. 고정 경로를 prop 으로 바꾼다(기본값은 현재 값).
5. OAuth 제공자를 toolkit 과 같은 5종으로 넓히고, 라벨을 다국어·`mode` 에 맞춘다.
6. 남은 영문 고정 문구를 다국어 사전으로 옮긴다.

## 비목표

- toolkit 에 의존하지 않는다(런타임 의존성은 지금처럼 `zod` 하나). 판독 규칙은 계약 문서를 따라 자체 구현한다.
- 클라이언트 측 입력 검증 규칙(로그인 비밀번호 최소 6자 등)은 바꾸지 않는다. 최종 판정은 서버가 하고, 서버 사유는 목표 2 로 화면에 나온다.
- 매직링크 폼 자체는 만들지 않는다. 버튼의 이동 경로만 prop 으로 연다.

## 설계

### 1. 오류 판독기 (`utils/read-auth-error.ts`, 내부)

```ts
export interface AuthErrorInfo {
  /** 화면에 표시할 문구 */
  text: string;
  /** 기계 분기용 키 — 표준 응답의 error.key, 문자열형 응답의 code. 없으면 undefined */
  key?: string;
  /** 표준 응답의 숫자 code(예: 40305). 문자열형이면 undefined */
  code?: number;
  /** 필드별 첫 사유 — details.fieldErrors 의 각 배열 첫 항목 */
  fieldErrors: Record<string, string>;
  /** HTTP 상태. 네트워크 오류면 0 */
  status: number;
  /** 네트워크 오류 등 응답을 받지 못한 경우 true */
  network: boolean;
}

export function readAuthError(status: number, body: unknown, fallback: string): AuthErrorInfo;
```

판독 규칙은 toolkit 계약과 같다.

| 응답 형태 | `text` | `key` | `fieldErrors` |
|---|---|---|---|
| 표준 `{ error: { code, key, message, userMessage, details } }` | `userMessage.description` → `fallback` | `error.key` | `error.details.fieldErrors` |
| 문자열형 `{ error: "…", code?, details? }` | `error` → `fallback` | `code` | `details.fieldErrors` |
| JSON 이 아니거나 형태 불명 | `fallback` | 없음 | `{}` |

- 표준 응답의 `message` 는 개발자용 영문이라 **표시하지 않는다**. `userMessage` 가 없으면 폼의 다국어 기본 문구(`fallback`)를 쓴다.
- 본문 파싱 실패(`res.json()` 예외)도 형태 불명으로 처리한다. 지금은 5xx HTML 응답에서 예외가 나 네트워크 오류로 오인된다.

### 2. 폼의 오류 표시

- 각 폼은 `!res.ok` 에서 `readAuthError` 결과를 받아 `error`(폼 단위)와 `fieldErrors`(필드 단위) 상태를 함께 채운다.
- `fieldErrors` 의 키가 폼에 있는 입력(`email`·`password`·`name`·`extraFields[].name`)과 맞으면 그 입력 아래에 표시한다. 맞지 않는 키는 무시한다.
- 필드 오류가 하나라도 표시되고 폼 단위 문구가 그 사유와 같으면 폼 단위 문구는 숨긴다(같은 문장을 두 번 보이지 않기 위해).
- `LoginForm` 미인증 판정: `key === 'EMAIL_NOT_VERIFIED'` 이면 `messages.emailNotVerified` 를 표시한다(문자열형 `code` 도 같은 `key` 로 들어오므로 하나의 조건으로 충분하다).

### 3. 훅

```ts
interface AuthFormHooks<TSubmit, TSuccess = unknown> {
  onBeforeSubmit?: (data: TSubmit) => Promise<boolean>;
  onSuccess?: (result: TSuccess) => void;
  /** message 는 지금과 같은 문구. info 는 0.7 에서 추가된 구조화 정보 */
  onError?: (message: string, info: AuthErrorInfo) => void;
}
```

- `onError` 는 두 번째 인자만 추가하므로 기존 `(message) => …` 구현은 그대로 동작한다.
- 모든 실패 경로(서버 실패·네트워크 오류·OAuth 시작 실패)에서 `onError` 를 부른다.
- `ForgotPasswordForm`·`ResetPasswordForm`·`EmailVerificationForm` 에 같은 `hooks` 를 추가한다. 앞의 두 폼은 `onBeforeSubmit` 도 받는다. `EmailVerificationForm` 은 자동 제출이라 `onSuccess`·`onError` 만 받는다.
- `AuthProvider.login` 이 던지는 오류는 `AuthError`(`Error` 하위 클래스, `info: AuthErrorInfo` 보유)로 바꾼다. `message` 는 `info.text` 라 기존 `catch (e) { e.message }` 는 그대로 동작한다.

### 4. 경로 prop

| 폼 | prop | 기본값 |
|---|---|---|
| `LoginForm` | `forgotPasswordUrl` | `'/forgot-password'` |
| `LoginForm` | `signupUrl` | `'/signup'` |
| `LoginForm` | `magicLinkUrl` | `'/auth/magic-link'` |
| `SignupForm` | `loginUrl` | `'/login'` |

- 기본값이 현재 고정값이라 동작은 바뀌지 않는다. `Page`·`Screen` 은 이 prop 을 폼으로 그대로 넘긴다.
- 링크 prop 에는 동일 출처 검사를 걸지 않는다. 기존 `loginUrl`·`resendUrl` 도 검사하지 않으며, 새 prop 만 검사하면 같은 종류의 prop 끼리 동작이 갈라진다. 출처 검사는 지금처럼 `window.location` 으로 이동하는 리다이렉트(`redirectAfterLogin` 등)에만 적용한다.

### 5. OAuth

- `OAuthProvider = 'google' | 'github' | 'kakao' | 'meta' | 'microsoft'` 로 넓힌다. 아이콘을 추가한다.
- 라벨을 사전으로 옮긴다: `messages.oauth.continueWith` / `signUpWith`(`{provider}` 자리표시자), 제공자 표시명은 `messages.oauth.providers.<id>`. `mode` 가 `signup` 이면 `signUpWith` 를 쓴다.
- `OAuthButtons` 에 `onError?: (info: AuthErrorInfo) => void` 와 `locale`·`messages` prop 을 추가한다. `/oauth/login` 실패와 `loginUrl` 누락을 오류로 알린다. 폼 안에서 쓰일 때는 폼이 이 오류를 폼 단위 오류로 표시하고 `hooks.onError` 로 넘긴다.
- 유니언을 넓히는 변경이라 값을 넘기는 쪽은 그대로 동작한다. `OAuthProvider` 로 망라형 `switch` 를 쓰는 소비자 코드만 타입 오류가 날 수 있다 — README 마이그레이션에 적는다.

### 6. 다국어

- `forgotPassword`·`resetPassword` 섹션에 `failed`·`networkError` 키를 추가하고 `'Failed'`·`'Network error'` 고정 문구를 대체한다(ko·en·ja). 기존 사전이 `login.networkError` 처럼 화면별 섹션에 키를 두므로 같은 구조를 따른다.
- `oauth.*` 키를 추가한다(위 5).

## 호환성

| 변경 | 기존 소비자 영향 |
|---|---|
| 오류 판독기 | 문자열형 응답은 지금과 같은 문구가 나온다. 표준 응답이 새로 읽힌다 |
| 필드 오류 표시 | 서버가 `details.fieldErrors` 를 주는 경우에만 새로 표시된다 |
| `onError` 두 번째 인자 | 없음 |
| 새 `hooks`·경로 prop | 없음(선택 prop, 기본값 = 현재 값) |
| `OAuthProvider` 확장 | 망라형 `switch` 소비자만 타입 오류 가능 |
| `AuthProvider.login` 오류 클래스 | `instanceof Error`·`message` 동일 |

따라서 0.7.0 은 minor 다. toolkit 0.22(표준 응답 기본값)보다 **먼저** 발행한다.

## 테스트 계획

- **단위**: `readAuthError` 변환 표(표준·문자열형·형태 불명·`userMessage` 없음·`fieldErrors` 있음/없음·네트워크 오류).
- **폼**: 폼마다 두 응답 형태로 실패 응답을 주고 표시 문구·필드 오류·`onError` 인자를 확인한다. 경로 prop 기본값과 지정값. `LoginForm` 미인증 판정(`key`).
- **OAuth**: 5종 렌더, `mode` 별 라벨, 실패 응답에서 `onError`.
- **계약 테스트(신규)**: toolkit 을 **테스트 전용 devDependency** 로 두고, 메모리 저장소를 주입한 실제 toolkit 인증 핸들러를 `fetch` 대역으로 연결해 폼을 제출한다. `errorFormat` 두 값 모두에서 같은 화면 결과가 나오는지 확인한다. 양쪽 단위 테스트가 각자 통과해도 둘 사이의 계약 불일치는 잡히지 않기 때문이다. 런타임 의존성은 늘지 않는다.
- **접근성**: 필드 오류에 `aria-describedby`·`aria-invalid` 를 연결하고 기존 axe 테스트에 포함한다.

## 문서

- README: 오류 처리 절(두 형태 지원, `fieldErrors` 표시, `onError(message, info)`), 경로 prop, OAuth 5종, 0.7 마이그레이션(망라형 `switch`).
- `docs/preview-*.html`: OAuth 5종과 필드 오류 상태를 추가한다.

## 결정 사항

1. **중복 문구 숨김**: 필드 오류와 폼 단위 문구가 같으면 폼 단위 문구를 숨기는 규칙(2절)을 기본으로 하고, 끄는 prop 은 두지 않는다. 같은 문장을 두 번 보이고 싶은 경우가 없고, 필요해지면 나중에 추가해도 호환된다.
2. **계약 테스트용 toolkit 버전**: devDependency 를 `^0.21.0` 으로 둔다. 0.x 의 caret 은 minor 를 고정하므로, 기본값이 바뀌는 0.22 로 올릴 때는 반드시 의도적으로 갱신하게 된다.
