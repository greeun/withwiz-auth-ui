# 0.8 — 성공 후 처리 훅·성공 봉투 판독·가입 추가값

- 상태: 확정
- 동기: 소비 앱이 로그인 성공 후 (1) 역할에 따라 다른 경로로 보내거나 (2) 비동기 후처리를 끝낸 뒤 이동하거나 (3) 후처리 실패 시 머물러야 하는데, 0.7 은 `onSuccess` 를 기다리지 않고 `redirectAfterLogin` 으로 즉시 이동한다. 또 `{ success, data }`(toolkit `IApiResponse`) 성공 봉투의 `data.user`·`data.loginUrl` 을 읽지 못하고, 가입 요청에 입력란 없는 값(예: 언어)을 실을 수단이 없다.

## 결정
1. `hooks.onSuccess(result, { body })` — LoginForm·SignupForm 은 await 한다. `/` 로 시작하는 문자열 또는 http(s) URL 반환 = 이동 경로(같은 출처 검사, 반환 타입은 `unknown`), undefined = 기존 기본 경로, 예외 = 머묾 + 오류 표시 + onError(key `SUCCESS_HOOK_FAILED`). 별도 `resolveRedirect` prop 은 API 증가라 채택하지 않음. 그 외 폼은 `onSuccess(undefined, { body: null })` 을 호출하고 반환값을 무시한다.
2. 성공 본문 판독 `readSuccessField(body, key)` — 평면형 우선, 없으면 `body.data`. LoginForm·SignupForm·OAuthButtons·AuthProvider 에 적용. prop 없이 자동.
3. `SignupForm.extraPayload` — 폼 값(name·email·password·extraFields)이 항상 우선. `onBeforeSubmit` 은 폼 값만 받는다.
4. 비밀번호 강도 표시는 넣지 않음(ResetPasswordForm 이 입력값을 노출하지 않아 slot 불가).
5. 폼 수준 오류(`wiz-auth-error`)에 `role="alert"` — 오류가 보조기술에 알려지지 않던 문제 보완(Login·Signup·Forgot·Reset).
6. `ForgotPasswordForm`·`ResetPasswordForm` 에 `slots.header` — LoginForm·SignupForm 과 같은 규칙(undefined = 기본 제목, null = 숨김, 노드 = 대체)으로 제목을 숨기거나 바꾼다. 성공 상태 화면은 영향 없음. 자체 레이아웃에 제목을 둔 소비자에서 제목이 두 번 나오던 문제 해소.

## 호환성
모두 추가 변경. 한 인자 `onSuccess` 는 그대로 동작한다. 반환값을 쓰지 않던 소비자는 동작이 같다. 다만 다음은 달라진다.
- SignupForm 은 성공 화면을 `onSuccess` 가 끝난 뒤 띄운다(0.7 은 호출 직전).
- `/` 로 시작하는 문자열이나 http(s) URL 만 이동 경로로 쓴다. 그 밖의 반환값(예: toast id)은 무시하고 기본 이동을 따른다.
- 비동기 `onSuccess` 는 끝날 때까지 이동을 미루고, reject 되면 폼에 머문다. 기다리지 않던 후처리(분석 등)의 오류는 핸들러 안에서 잡아야 한다.
- 예외는 메시지가 있는 `Error` 를 던져야 그 메시지가 보인다(다른 값은 폼의 일반 대체 문구). 새 메시지 키는 추가하지 않는다.
- `hooks.onSuccess` 를 직접 호출하는 코드는 두 번째 인자 `{ body }` 를 넘겨야 한다.
- 반환 타입은 `unknown` 이라 값을 반환하던 0.7 핸들러도 그대로 컴파일된다.
