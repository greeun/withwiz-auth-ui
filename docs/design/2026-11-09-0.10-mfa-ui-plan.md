# auth-ui 0.10.0 MFA(TOTP) 화면 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** toolkit 0.30.0 의 MFA 서버 계약을 쓰는 로그인 2단계 화면, OAuth 용 코드 입력 화면, 계정 설정용 MFA 관리 컴포넌트를 auth-ui 에 추가한다.

**Architecture:** 서버 호출과 응답 해석은 `src/utils/mfa-api.ts` 하나에 모으고, 입력 검증·오류 문구 선택은 `src/utils/mfa-input.ts` 에 둔다. 코드 입력란(6자리 ↔ 복구 코드 전환)은 내부 컴포넌트 `MfaCodeField` 하나를 `MfaChallengeForm`·`MfaSettings` 가 함께 쓴다. `LoginForm` 은 `MFA_REQUIRED` 를 받으면 자기 본문 대신 `MfaChallengeForm` 을 그린다.

**Tech Stack:** React 18/19, TypeScript, zod 4(기존), `uqr@0.1.3`(신규, QR 행렬), vitest + Testing Library(jsdom).

**Spec:** `docs/design/2026-11-09-0.10-mfa-ui-design.md` (상위: toolkit `docs/auth/2026-11-08-mfa-totp-design.md` 4-1·4-2절)

## Global Constraints

- 새 런타임 의존성은 `uqr` 하나, `"uqr": "0.1.3"`(범위 기호 없이 정확한 버전). `tsup.config.ts` 의 `external` 에 `'uqr'` 추가.
- 새 export 서브패스 없음. `components`·`screens`·`pages`·`i18n`·`types` 기존 진입점에 추가한다. `MfaCodeField`·`MfaQrCode` 는 공개하지 않는다.
- 새 클래스는 `wiz-auth-mfa-*`. `src/styles/auth.css` 의 기존 `@layer` 안에 추가하고, 새 CSS 변수(토큰)는 만들지 않는다(`auth-css.test.ts` 의 "24 tokens" 유지).
- 인라인 `style` 금지(`no-inline-styles.test.tsx` 규칙). `unstyled` 이면 패키지 클래스를 빼고 소비자 `classNames` 만 남긴다(기존 `cls()` 패턴).
- 복구 코드·비밀 키·`mfaToken` 을 `localStorage`·`sessionStorage`·URL 에 쓰지 않는다. 복구 코드는 컴포넌트 상태에만 두고 [완료] 시 지운다.
- `MFA_REQUIRED` 가 오지 않는 경로의 `LoginForm`·`AuthProvider` 동작은 0.9 와 같다. 기존 테스트는 수정 없이 통과해야 한다.
- 6자리 코드를 다 입력해도 자동 제출하지 않는다. 잠금 시간은 `Math.ceil(retryAfter / 60)`(최소 1)분으로 표시하고 카운트다운하지 않는다.
- 요청은 모두 `authFetch`/`authPost`/`authGet`(`credentials: 'include'`)을 쓴다. 관리 화면은 쿠키 인증만 지원한다.
- 기본값: `apiBasePath='/api/auth'`, `redirectAfterLogin='/'`, `loginUrl='/login'`, `recoveryCodesFileName='recovery-codes.txt'`, `locale='ko'`.
- 서버 경로: `POST {api}/mfa/verify`, `GET {api}/mfa`, `POST {api}/mfa/setup`, `POST {api}/mfa/enable`, `POST {api}/mfa/disable`, `POST {api}/mfa/recovery-codes`.
- 버전 `0.10.0`. 변경 이력은 README 의 `## Migration` 아래 `### 0.10` 절에 둔다(이 저장소에는 CHANGELOG 파일이 없다).
- 테스트는 변경 범위만 실행한다(`pnpm vitest run <파일>`). 전체 스위트는 마지막 Task 에서 한 번만 실행한다.

## Review Focus

1. **cookie 모드 로그인**(본문에 `mfaToken` 없음): 2단계로 바뀌고, 검증 요청 본문에 `mfaToken` 키가 아예 없어야 한다 → Task 3·Task 1 테스트.
2. **`retryAfter` 가 없는 `MFA_LOCKED`**(프록시가 본문을 바꾼 경우 등): 분 표시 없이 서버 문구로 떨어지고 제출은 비활성 → Task 1·Task 2 테스트.
3. **서버 `redirectTo` 가 다른 출처 URL**: `safeRedirectTarget` 가 막고 `redirectAfterLogin` 으로 간다 → Task 2 테스트.
4. **복구 코드 모드에서 공백·대문자 섞인 입력**(`" ABCD-1234 "`): 앞뒤 공백만 잘라 그대로 보내고 클라이언트가 거부하지 않는다 → Task 1 테스트.
5. **`navigator.clipboard` 없는 환경**(http 개발 서버): 복사 버튼이 사라지고 다운로드·완료 흐름은 그대로 동작 → Task 7 테스트.
